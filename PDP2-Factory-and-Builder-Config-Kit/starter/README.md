# Factory and Builder Config Kit: Learner baseline

A working report-construction and exporter baseline.

The starter already runs and passes the contract. Preserve behavior while changing the representation; compare the reference after a green refactor.

## Required behavior

Report(title, sections, include_footer, tag) owns a copy of its input section list. A builder supports add_section, tagged, with_footer and build. Every build returns an independent report: later builder edits and edits to a returned report leave earlier reports and later builder results independent.

make_exporter accepts exactly markdown or text and returns a callable report-to-string exporter in both roles. Unknown string formats raise ValueError; non-string formats raise TypeError. Titles, sections and supplied tags must contain a non-space character; exact text is retained. The footer flag is a boolean. Exporters revalidate mutable report state and preserve the order of sections without mutation.

Core: replace function exporters with callable exporter objects while preserving every output and boundary. Explain why a named constructor/helper is enough for a small configuration and why the larger staged build benefits from a builder. Optional Config Kit: build two report variants from one builder, modify a returned report and prove independent snapshots; add and document one deliberately separate output feature after the core refactor is green.

## Run and check

Use CPython 3.14 for native checks. From this imported folder:

~~~sh
python main.py
python -B -m unittest discover -s . -p test_contract.py -v
python -m mypy --strict --no-incremental --python-version 3.14 main.py
~~~

The program uses only the standard library. The included requirements-dev.txt pins the optional native checker and its tools. Install it in a virtual environment before the checker command; see the repository setup guide for platform-specific commands.
